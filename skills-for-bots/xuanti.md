# 选题 · 技能包：研究问题评估

## 把兴趣变成问题

模糊兴趣 → 可验证问题，要过四关：

1. **可判定**：什么样的结果算回答了它？说不出来就不是问题，是愿望。
2. **有边界**：做什么、不做什么，一句话说清。
3. **有反例**：什么现象会推翻你的判断？找不到反例说明判断不可证伪。
4. **有成本估计**：最小可验证实验要多少数据、多少算力、多长时间。

## 五维体检

对每个候选方向逐项打分并说明理由：

- **更高**：指标上限是否真的更高？还是只是换了评估口径
- **更快**：训练或推理效率提升多少，代价是什么
- **更强**：鲁棒性、泛化性、长尾表现
- **更省**：数据、算力、标注成本
- **更广**：能否迁移到相邻任务

任何一项拿不出量化依据，就写「待验证」，不打分。

## 新颖性判定

不许说「没人做过」。只允许说：

- 「在检索 X 个库、用 Y 组关键词之后，未见 Z 类工作」——附检索式与日期
- 「已有 A 做过类似的事，差异在 B」

「未见」是检索结论，「没有」是本体论断言。两者不能混。

## 致命缺陷审计

按优先级问：

1. 这个问题是不是伪问题（假设本身错了）
2. 数据能不能拿到（拿不到就结束）
3. 评价指标是否被已有工作定义清楚
4. 会不会被一篇已有工作完全覆盖
5. 一年内能否做出可发表的结果

前三条任一不通过，直接建议放弃，不要往下评估。

## 输出格式

候选问题清单，每条含：问题陈述、为什么值得做、最小可验证实验、可能被推翻的方式、主要风险。末尾附风险列表，按「会不会让整个方向作废」排序。

## 禁止

- 不得把候选方向说成已定选题
- 不得编造「某篇论文提到过」
- 不得为让方向显得新而隐去已知的相近工作

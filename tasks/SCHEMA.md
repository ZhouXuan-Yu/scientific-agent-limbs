# 任务单规范 v1

大脑向末端下发工作的最小契约。一张任务单是一个 JSON 文件，对应一个物理目录。

没有这张单子，下发就是"发一条消息"，回收就是"翻聊天记录"。43 个会话用 session id 手记，到十个并行任务就会失控。

## 文件位置

```
OH-WorkSpace/tasks/
  T20261019-01-a3f2.json      任务单
  T20261019-01-a3f2/          产物目录，与任务单同名
  SCHEMA.md                   本文件
```

单文件、纯文本、可 diff、可 git。不引入数据库：任务数量在百级，扫描目录足够快，而数据库会让"人能不能看懂"这件事变难。

## 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 任务号，格式 `T<YYYYMMDD>-<两位序号>-<4位随机>` |
| `title` | string | 是 | 一句话说明，不超过 40 字，用于列表呈现 |
| `goal` | string | 是 | 要达成的结果，描述"什么算做成了"，不写"怎么做" |
| `acceptance` | string[] | 是 | 可判定的验收条目，每条是一个能回答是/否的陈述 |
| `limb` | string | 是 | 执行末端：`dsh` / `local` / `zotero` |
| `assignee` | string\|null | 否 | DSH 侧承接者，如 `Chief`、`写作`；本地任务为 null |
| `sessionId` | string\|null | 否 | DSH 会话 id，下发后回填 |
| `state` | string | 是 | 见状态机 |
| `createdAt` | string | 是 | ISO 8601 |
| `updatedAt` | string | 是 | ISO 8601 |
| `artifacts` | string[] | 否 | 产物路径，相对 `OH-WorkSpace`，可多个 |
| `failure` | string\|null | 否 | 失败原因，`state=failed` 时必填 |
| `notes` | string[] | 否 | 追加式备注，每条形如 `ISO时间 | 内容` |
| `history` | object[] | 是 | 状态迁移记录，`{at, from, to, note}` |

## 状态机

```
queued ──► dispatched ──► running ──► done
   │            │            │
   │            │            └──────► failed
   └────────────┴────────────────────► cancelled
```

| 状态 | 含义 | 谁能推进 |
|---|---|---|
| `queued` | 已定义，未下发 | 大脑 |
| `dispatched` | 已下发到末端，尚未确认开始 | 大脑（下发动作成功后自动置位） |
| `running` | 末端确认在执行 | 末端回报，或大脑读回确认 |
| `done` | 验收条目全部满足 | 大脑 |
| `failed` | 终止且不可恢复 | 末端回报或大脑判定 |
| `cancelled` | 主动废弃 | 大脑 |

规则：

- `done` 只能由大脑置位，且必须逐条核对 `acceptance`。末端自称完成不等于完成。
- 状态只能前进，不能回退。需要重做就新建任务单，并在 `notes` 里写清与旧单的关系。
- `cancelled` 从任何状态可达。

## 验收条目的写法

不好：`完成实验`、`效果良好`、`整理文献`。
好：`产出 tasks/T.../result.md，包含至少 5 条结论，每条标注证据来源`。

判断标准：换一个人拿着这条，能不能在不问作者的前提下判定通过或失败。不能，就重写。

## 产物规则

- 产物一律放 `tasks/<id>/`，不放工作区根目录。
- 路径写进 `artifacts`，相对 `OH-WorkSpace`，统一用正斜杠。
- 任务单本身不放产物内容，只放指针。这样任务单永远是小文件，适合快速扫描。

## 命名规则

`T` + 本地日期 8 位 + 当日序号 2 位 + 4 位十六进制随机。

例：`T20261019-03-9f1c`。同日按序号递增，随机段防止并发创建撞号。任务号只增不减，删除的任务单留档不释号。

## 与末端的交接

下发时，大脑把任务单渲染成固定格式的文本，附在指令前：

```
[任务单 T20261019-03-9f1c]
目标：...
验收标准：
1. ...
2. ...
产物目录：tasks/T20261019-03-9f1c/
回报要求：完成后回复做了什么、产物路径、哪条验收标准存疑。
```

末端回报后，大脑逐条核对验收标准，再置 `done` 或 `failed`。这条纪律的意义在于：**任务状态由证据决定，不由自述决定。**

## 不做什么

- 不做优先级字段。排序靠人，不靠字母。
- 不做预估工时。现在没有可靠的估时数据，填了也是猜。
- 不做依赖图。任务量到几十个之前，文字里写一句"等 T... 完成"比建图便宜。
- 不做自动重试。失败原因没读明白就重试，只会重复失败。
